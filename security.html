Reinforcement learning for dataflow-aware fuzz-driver generation

RLDriver turns fuzz-driver quality into a structured reward environment, aligning a code model with the program properties that determine whether library behavior is actually reachable.

First-author manuscriptSubmitted to ICSE 2027 · under reviewC/C++ librariesStatic analysis + GRPO
RLDriver · System overview

From offline alignment to downstream fuzzing

Next-token prediction does not directly optimize whether a generated driver invokes the requested APIs, explores related behavior, composes stateful calls, or exposes those calls to fuzzer input.

RLDriver builds a library-side API dependency graph, generates task-conditioned drivers, analyzes their realized dataflow, and uses four qualitative rewards in a customized GRPO loop. The aligned model then serves as the generation policy in a conventional coverage-guided fuzzing workflow.

Target API alignment

Measures whether the generated driver invokes the APIs requested by the task.

API-surface exploration

Rewards broader use of relevant public APIs around the target behavior.

Stateful interaction

Checks whether API calls form a connected producer–consumer dataflow rather than isolated statements.

Fuzzer-input propagation

Measures how many API calls receive values derived from the fuzzer’s input bytes.
